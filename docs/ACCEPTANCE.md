# 验收与开源边界

状态：验收计划，不代表已运行实现测试。修订日期：2026-10-12。当前范围见 [RFC](RFC-001-SERVER-RUNTIME.md)。

验收分为最小核心、受控操作和宿主集成。数据库、队列及多 worker 测试不作为运行最小核心的前置条件；宿主承诺相关能力时必须验证。

## 最小核心验收

| 领域 | 必须通过的验证 |
| --- | --- |
| 无外部设施嵌入 | 单个 Go 程序传入可信身份、历史、Provider 和工具即可运行；不需要 PG/Redis、daemon、RPC、Web 框架或完整 SDK/Eino |
| 助手与模式 | 两个 Definition 使用各自工具集合与独立上下文；Chat/Agent 共用执行链，切换模式不扩大权限，也不自动后台化 |
| 模型调用 | 适配固定 Router HTTP 客户端；模型不能覆盖 endpoint、凭据、提示模板或工具定义 |
| 工具注册 | 未注册名称/版本拒绝；缺失或非法 Effect 拒绝注册；schema、业务范围与响应大小检查生效；无动态代码加载 |
| 授权 | 有工具执行缺少 Authorizer 时拒绝；每次调用重新检查账户/资源/参数；检查错误或撤权后不执行；纯文本 Chat 可不注册工具 |
| 有界执行 | 总时长、轮数、工具次数、字节、重试与并发有效；重复调用停止；用户/模型不能扩大预算；超时取消传到工具客户端 |
| 流式模型 | UTF-8/网络分片、模型工具调用片段、断流/错误正确处理；不完整流不能产生成功；临时预览与最终结果区分 |
| 公开事件 | 回复增量和实际查询进度带执行/轮/代次标识；不输出私有推理、原始错误、凭据或完整工具结果 |
| 证据与结果 | 403/404/超时/不合法产物区分；编造证据 ID 拒绝；陈旧和未接入明确标注；诊断完成不宣称问题已修复 |

使用 scripted provider 和 spy ToolExecutor 验证实际调用、顺序、次数与结果，不能仅检查提示词文本。虚构示例不访问生产、不投递真实消息、不制造线上失败。核心无法强制杀死任意 Go 回调，应以支持 context 的测试适配器验证取消传播。

## 受控操作与审批验收

即使真实宿主只接入读取，也用显式启用的虚构写工具验证协议：

| 情形 | 必须证明的行为 |
| --- | --- |
| 普通授权读取 | 直接执行，人工审批不是每次查询的额外前置条件 |
| 写工具未注册/无权 | 无副作用；模型切换模式或声称已批准不能绕过 |
| 必须审批但通道缺失/pending/拒绝 | 返回待批准或拒绝结果，工具未执行；不静默放行、不产生虚假完成 |
| 审批正常路径 | 先展示具体提案并批准，再复核权限/预算/目标状态，最后执行 |
| 批准过期、跨账户、参数/资源/版本变化 | 批准无效；关键目标状态变化重新确认；公开事件不能充当批准凭证 |
| 同一次操作重复提交 | 默认核心不自动重试写；虚构宿主以稳定 OperationID 和业务去重确保相同意图只生效一次 |
| 两次合法的相同参数操作 | 不被永久参数去重误吞；由宿主明确为两个意图分配不同操作标识 |
| 请求超时/取消但操作已生效 | 报告 unknown 或查询业务结果，停止自动操作；不把超时当作“没执行”，不自动回放 |
| conflict / partial | 实际影响与未完成项分别报告，不折叠为 applied，不自行补偿或扩大范围 |
| 调用/影响超出额度 | 写调用次数和业务资源上限有效，单对象工具不能变成任意批量操作 |
| 操作成功但答案/保存失败 | 不重做副作用；依据业务操作记录确认结果；审计与模型摘要分离 |

一次性批准与业务执行之间的故障也要覆盖；审批记录本身不能证明业务 exactly-once。去重和结果查询由宿主/业务接口保证，不由 ToolSpec 布尔标记或进程内锁保证。

## 虚构公开示例

默认创建 data-analyst 与 artifact-diagnostics，只注册查询工具并使用内存记录，历史由调用方传入。案例覆盖未到排程、生产任务失败、产物缺失、消费者版本不兼容、403、来源不可达、陈旧快照及日志未接入。

受控操作示例另行显式启用：一个虚构任务的诊断 → 展示重试提案 → 宿主批准 → job.retry → 查询结果，包含待批准、重复、部分完成和结果不明案例。不把写工具注册到默认只读助手。

所有案例只用虚构记录和泛化标识，不加入真实域名、人员、运行 ID、账单、日志、存储键、对象正文或平台导出。

## 宿主按需集成验收

| 宿主启用的能力 | 对应验证 |
| --- | --- |
| 登录与账户历史 | 账户/助手隔离，当前权限筛选上下文，列表/结果读取授权，保留/到期策略 |
| 会话切换、继续与刷新 | 活跃执行控制；旧流/迟到事件不串入新会话；保存失败不发布持久成功；未完成轮明确标记 |
| HTTP/SSE | 旧接口兼容，断线/取消语义明确，重连不隐式创建任务或操作；结果/长订阅复核权限 |
| 真实具名操作 | 按具体业务验证影响范围、审批、持久去重、未知结果查询、审计和并发目标状态检查 |
| 持久后台任务 | 原子接收与幂等冲突、分发丢失/重复、领取/租约、旧 worker 提交、执行/提交资格及版本兼容 |
| 多 worker 接管 | 崩溃/租约失效后的状态与预算一致；已完成步骤复用；写操作不自动回放；取消不自动恢复 |

只在启用持久分发/接管时，用一次性真实 PG/Redis 或宿主实际组件做并发与故障验证。不把“部署多个 API Pod”误当成“已经实现持久 Agent 任务”。

## 公共与私有边界

| 公开仓库 | 宿主独立维护 |
| --- | --- |
| model/tool/runner/event 协议与实现 | 企业统计规则、身份映射、真实数据 |
| 授权与可选审批接口、受控操作合同 | IAM/角色、审批 UI/系统、业务去重与审计 |
| 虚构嵌入 demo 与协议测试 | SQL、对象路径、产物合同、内部日志/API |
| Provider 适配与源码引入清单 | 模型配置、凭据、历史存储、任务调度与部署 |
| 许可证、NOTICE 和设计/安全文档 | 平台导出、线上截图和排查记录 |

不把私有项目整体 fork 为公开仓库。首次发布和每次公开更新核对 tracked 文件及新增历史；秘密扫描辅助人工检查，不替代内容核对。

## 源码引入与交付

纯核心按清单复制、调整 import 后可在虚构宿主构建，不依赖完整 SDK、私有包或新部署设施。固定上游版本，保留来源 LICENSE/NOTICE、文件映射和本地改造。普通 Go module 导入也可选择。

首个宿主先接入既有 Router、查询/诊断工具和历史/UI，保留旧接口兼容及切回路径。升级比较来源差异并运行已启用功能的回归；公开核心支持写操作不等于宿主获得生产写权限。

当前仓库只有设计文档。实现、示例和以上验收均需后续交付，不把文档校验报告当作运行回归结果。
