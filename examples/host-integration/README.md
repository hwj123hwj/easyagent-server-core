# 宿主接入案例：企业用量与成员权限

这是从企业应用集成中提炼的**匿名、离线参考案例**：一个对话既能查询业务数据，也能准备需要用户确认的管理操作。身份、成员、组织、日期、金额、审批和模型回答全部使用重新编写的虚构夹具，公开内容仅包含通用集成结构。

示例真正调用本仓库的 `runner.Run`、`Definition.Discovery`、`Authorizer`、`ApprovalGate` 和 `runner.Continue`。宿主在自己的代码中管理身份、会话、业务范围、提案、事务和审计。无需密钥、数据库或网络；不连接任何实际消息平台或客户服务。

## 运行与阅读

在仓库根目录使用 Go 1.24+：

```sh
go run ./examples/host-integration
go run ./examples/host-integration -scenario pending
go run ./examples/host-integration -scenario cancelled
go run ./examples/host-integration -scenario revoked
go run ./examples/host-integration -scenario changed
go run ./examples/host-integration -scenario reset
go run ./examples/host-integration -scenario duplicate
go run ./examples/host-integration -scenario unknown
go test -race ./examples/host-integration
```

| 文件 | 阅读重点 |
| --- | --- |
| [main.go](main.go) | 两条普通消息、一次决策及安全结果展示 |
| [host.go](host.go) | 身份绑定、授权版本、会话隔离、提案保存、确认、历史和发布门禁 |
| [tools.go](tools.go) | 具名业务查询、能力组、新鲜读取、版本条件修改与业务审计 |
| [scripted.go](scripted.go) | 可重复的离线模型协议夹具；生产替换成自己的 Provider |
| [host_test.go](host_test.go) | 真实调用核心的越权、续聊、确认、并发和未知结果回归 |

首次运行依次输出三条 JSON：跨域查询完成且写入为0；后续消息形成待确认预览且写入仍为0；确认后执行固定操作，写入为1、模型调用为0。`duplicate` 再次确认同一提案，写入仍为1。

`revoked`、`changed`、`reset` 和 `unknown` 是刻意演示的拒绝/异常场景，预期验证成立时 CLI 也正常退出。读取 `state`、`operation_status` 和 `business_writes`，不能以进程退出码替代业务成功。`unknown` 模拟业务已生效后确认回执丢失：状态必须保持未知，不能自动再做一次来补回答。

## 一段会话的完整路径

```text
可信通道识别发送者 → 解析现有账户能力与数据范围
    → 创建当前身份的工具注册表和简短能力目录
    → Run：发现业务工具 → 查询用量 → 切到管理工具 → 查询权限
    → 保存本轮授权历史
下一条消息：“让他成为分析员，先给我看预览”
    → 同一会话历史 + 本轮重新发现工具
    → 重新查询目标当前状态 → 准备固定提案 → pending_approval
    → 宿主保存原 Proposal，展示影响和有效期
真实用户确认 → 按提案 ID 从宿主加载原操作
    → 核对操作者、通道、会话代次、权限版本和期限
    → Continue（零模型调用）
    → 重新鉴权、核对资源版本 → 条件修改 + 消费批准 + 审计
    → 保存并展示正式结果
```

普通消息由 Agent 选择工具并承接上下文。`scripted.go` 的固定调用序列只为离线测试；宿主没有“出现某个关键词就授权”、代词提取或人工拼接目标的业务路由。

## 1. 身份先于工具

`memoryHost.message` 的 sender/channel 是可信登录或消息适配器提供的字段。示例用内存账户模拟这种映射；这些字符串本身**不是认证机制**，不能拿此函数直接搭一个接受客户端任意 sender 的公开接口。

真实宿主先验证登录/消息来源，再将通道用户标识映射到现有账户，读取其当前能力和数据范围。模型参数只包含业务目标，不包含可选择的操作者、租户或管理员身份。正文自称管理员、语音转写中的姓名、被 @ 的目标都不能替换发送者身份。平台提及信息应由适配器核实成稳定标识，目标重名时再澄清；普通追问可以继续使用已授权历史。

示例普通账户只能读本人；组织范围操作者能读本组织，并且另有管理能力时才能看到管理工具。`member-b` 位于另一组织，已通过回归验证越权拒绝。业务成员的 role 字段与操作者的 Manage 能力分开，修改成员字段不会自动扩大操作人的能力。

## 2. 两类能力，逐轮披露

- `business.usage`：本人/授权组织内的每日用量、成本和来源状态。
- `system.members`：本组织成员权限查询、准备经确认的单项修改。

宿主根据当前身份过滤注册表和目录。首轮模型只收到 `discover_tools`；选择业务组后下一轮才出现查询 schema，选择管理组后替换先前分组。`MaxActiveTools=3` 包括目录本身，允许管理查询和修改共同出现。对话历史继续保留，活跃工具不会随会话无限累积。

新消息需要重新发现；旧历史中的工具名和结果不激活工具，也不赋予权限。工具披露解决上下文和选择负担，实际执行仍由 Authorizer 和业务范围检查决定。需要更多分类时，在宿主扩展 ToolGroup，不向核心加入具体产品名或角色表，也无需先引入多 Agent 调度。

## 3. 新鲜读取与固定提案

`member.read` 在本次 Run 的局部闭包记录目标版本。`member.update.Prepare` 要求同轮读过目标且版本仍匹配，历史中的旧查询不能替代它。提案明确目标、旧值、新值和资源版本；此时写入计数保持0。

宿主保存原 `Proposal`。确认输入引用宿主的提案 ID 和用户选择；工具名、目标、参数及 Proposal 都从宿主记录加载。客户端的 `confirmed=true` 只是一项选择，不能当作身份或批准真实性的凭据。决策还要绑定真实操作者、通道、会话代次、授权版本、有效期和原提案。取消不调用模型，不产生业务副作用。

有效确认使用 `Continue` 执行保存的原提案，不重跑模型“再生成一次相似操作”。核心复核授权、指纹和资源；业务事务中还要按目标版本条件修改，覆盖检查与修改之间的竞态。仅在核心 Prepare 中检查版本，然后无条件 UPDATE，仍不够。

## 4. 结果、去重与审计分开表达

示例在同一内存临界区检查未消费批准、执行条件修改、消费批准并追加业务审计。重复/并发确认最多产生一次示例副作用；未知结果保留为 unknown，后续确认只返回已有未知记录，不自动重放。

内存临界区**仅证明单进程示意行为**。生产应在现有业务事务中原子保存操作 ID、准确载荷、批准消费、条件变更、结果和审计，并为相同 ID 不同载荷设置冲突保护。示例计数器生成的 ID 只在本次进程有效；生产须用持久唯一意图 ID。跨服务写入采用目标系统幂等键及结果核查，不能把一次性批准等同于外部系统只生效一次。

业务执行状态和消息投递状态也要分开：业务已确认成功后回答发送失败，应查询已有操作结果；发送超时没有回执时保留未知，不能重做业务或盲发第二份通知。示例没有消息发送器，也不宣称展示 JSON 就代表通道送达或用户已读。

## 5. 历史、会话与迟到结果

会话键包含租户、本人和通道，另记录会话代次与授权版本。新消息核对当前授权；权限版本变化会隔离旧历史；生产版本应覆盖能力和数据范围，不能只使用登录时间。reset 增加代次，旧预览不能继续执行，迟到回答也无法写回新会话。

暂停于审批时，模型可能已提出多个工具调用。宿主给每个未执行调用补上真实的“等待确认，未执行”工具结果，保持调用/结果配对；不伪造成功。确认/取消结果随后追加到同一会话。存储前使用公开 JSON 协议剥离 `ReasoningContent`，按完整用户轮限制历史大小。

历史中的业务结果仍可能是敏感数据，生产存储/恢复/导出必须再次按当前范围授权并落实保留策略。示例的“公开历史”指核心允许序列化的字段，不代表它可被匿名公开。

## 6. 数据口径属于业务工具

用量工具保留日期、输入/输出 Token、以最小货币单位表示的成本、币种、来源状态和报告发布标记。示例来源为 partial，仍可返回已知用量与金额；不能据此说报告已发布，也不能把未完成或缺失数据补成零。跨来源核对时分别检查实际产物、窗口、完成标记与报告状态，单次任务成功或队列为空不能代替业务证据。

真正的查询应复用宿主已有的业务服务和只读快照，返回经过权限过滤的明确投影；参数使用闭合 schema，不接受原始 SQL、任意 URL、脚本或完整管理员数据库连接。金额和大整数在适配/JSON转换时保持精度，不借助手重算已确认账单。

## 7. 接到生产时需要补上的部分

| 生产边界 | 本示例 | 真实宿主接法 |
| --- | --- | --- |
| 认证与成员目录 | 内存虚构账户 | 复用现有登录、正式身份映射和权限解析器 |
| 业务读写 | 固定事实、内存条件修改 | 复用现有业务服务、快照/事务与资源范围检查 |
| 历史、提案、操作与审计 | 进程内 map | 持久存储，精确版本绑定，事务与访问控制 |
| 输入去重与顺序 | CLI串行输入、单进程会话忙碌门禁 | 通道事件去重、每会话接纳顺序、迟到输入边界 |
| 后台任务与多实例 | 没有 worker/租约 | 独立 AI 接纳预算、持久租约、心跳、fencing与断线恢复 |
| reset 与停止 | 代次失效和发布门禁 | 另接协作式取消、持久状态，不能假设取消会回滚业务 |
| 审批交互 | 本机决策调用 | 已认证回调/文本决策、原通道绑定、过期与消费核对 |
| 回复与临时反馈 | 仅 stdout JSON | 持久发送意图、真实回执、未知结果保护、处理中反馈收尾 |
| 模型效果 | 固定协议夹具 | 真实 Provider 的工具选择/续聊/时延/拒绝与金额口径验收 |

不应把 map 换成数据库后就宣称跨 Pod 或故障恢复完成。先补齐各边界的事务/租约/消息合同，再回归并核对真实回执。本文不包含客户身份、员工、域名、连接信息、凭据、私有 SQL、生产日志、报告正文或部署资料。

完整核心合同见 [接入说明](../../docs/INTEGRATION.md) 与 [威胁模型](../../docs/THREAT-MODEL.md)。更短的协议演示见 [discovery](../discovery/main.go) 和 [embedded](../embedded/main.go)。
